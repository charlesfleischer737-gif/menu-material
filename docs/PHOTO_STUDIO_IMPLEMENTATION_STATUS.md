# Photo Studio — implementation and acceptance evidence

Updated September 17, 2026. Scope: the local working copy of Menu Material. **Not a production release or a claim that every acceptance criterion has passed.**

The product contract is [Photo Studio requirements and acceptance criteria](PHOTO_STUDIO_REQUIREMENTS.md). It contains 30 requirements and 208 numbered criteria. The pipeline identifier for this candidate is `studio-2026-09-17-studio-v6`. Existing API credentials are reused; they are not copied into this report. The local browser preview uses an isolated QA workspace with provider calls disabled. Automated provider responses are fixtures.

## What is implemented

- A photo-first studio with directly reachable upload, three starting choices, a selected-look summary, and one Create action. Polish my original is the safe starting choice unless an existing restaurant default applies.
- A focused visual catalog with plain-language search, typo handling, mood/category filters, examples, favorites, recently used looks and separate detail views. Search includes contextual control shortcuts, explicit scopes, saved-recipe matching, clear-filter recovery and honest related-match cues. Deliberate component overrides survive preset changes, with Undo. [Search evidence and limits](PHOTO_STUDIO_SEARCH_REVIEW_2026-09-17.md).
- Style details explain the effective setting, light, serving dish and camera angle, including retained custom choices and a separate favorite action. Recent styles now come from accepted creation/reuse records rather than selections; replay, rejected requests and library edits cannot fabricate or reorder use. [Style-detail and recent-use evidence](PHOTO_STUDIO_STYLE_DETAIL_REVIEW_2026-09-17.md).
- Occasion collections for Christmas, Game day, Valentine’s dinner and Summer drinks, each containing three different existing photographic treatments. These are curated scene and lighting collections; they do not claim new holiday decoration, licensed team imagery or live qualification.
- Setting, Serving dish, Light and Framing controls in a separate customizer. Drink/vessel conflicts require an explicit Keep my glass action. Browser Back returns through the studio’s sheets without discarding the draft.
- One inspiration-photo sheet is reachable from browsing and customization. It separates the dish from its reference, defers upload/application until explicit confirmation, preserves custom choices, supports replace/remove/retry and restores meaningful focus. Guest transfer maps the local reference to the uploaded asset. [Inspiration evidence and limits](PHOTO_STUDIO_INSPIRATION_REVIEW_2026-09-17.md).
- Saved references are checked before creation, with recovery actions for unavailable files. Server checks prevent new reservations for unusable references and recheck eligibility before provider dispatch; replay and completed-result reuse remain recoverable. Fifty-four dedicated API checks and missing-file browser recovery have local evidence. [Stored-reference recovery](PHOTO_STUDIO_INSPIRATION_REVIEW_2026-09-17.md#stored-reference-recovery-follow-up).
- Private named looks with names, duplication, reversible archive, explicit defaults for future Photo Studio drafts, and server-assigned configuration versions. Prior drafts retain captured recipes. Existing restaurant looks migrate without changing menu/post preferences or enabling a previously disabled default.
- Local guest photo/reference recovery with actual stored binary files and 24-hour inactivity expiry. Account transfer preserves progress. Repeated dish creation and photo uploads use stable intent identifiers and server-enforced deduplication; generation has its own idempotency key. Device favorites merge into the account collection after transfer.
- Honest queued/creating states without invented percentages. New jobs capture the image model, render settings, look context and full generation prompt. Reused results are identified and do not reserve another image.
- Full result review first, optional comparison, immutable original/history, and free local edits in a focused preview-and-controls dialog. Edits remain temporary until Save; Cancel, Escape and browser Back preserve the main draft. [Adjustment review and limits](PHOTO_STUDIO_ADJUSTMENT_REVIEW_2026-09-17.md).
- A finish sheet with a non-blocking food-review reminder, destination/crop preview, optional file name, actual export dimensions, full-quality export, download-start feedback and native sharing where supported. Exact selected assets carry into existing menus and Post Maker. Occasion context follows the photo into Post Maker.
- A dedicated food-error report covering ingredients, portions, plate/packaging, branding and artificial appearance. One complimentary correction can run at zero ordinary balance. Failed/still-inaccurate corrections restore one original image allowance once. The fourth automatic restoration within 30 days enters a real administrator review queue. Reports retain the original and previous outputs, and leave published snapshots unchanged.
- Sample-first sets of up to eight dishes. The owner explicitly approves the sample and continues with the remaining count/cost. The captured recipe applies to individual sources, with per-item review/retry and a download of selected approved full-quality files.
- Scoped administrator controls for an all-restaurant, pilot-only or paused creation rollout, individual looks and captured generation configurations. Queued work is checked again before provider submission; already submitted results remain recoverable. Paused owners get a focused recovery view with saved photos and free adjustments available. Unknown saved looks require an explicit replacement while preserving the original and overrides; captured historical recipes remain usable.
- A canonical event mapping, strict private-data exclusions, reviewed-asset eligibility for export signals, internal QA labeling, per-attempt download tracking and exact export-transform identities. Named-look reuse is recorded on accepted generation rather than selection. Duplicate approvals retain the first timestamp; late job recovery is separate from first completion.
- Foreground timing estimates separate decisions from upload, queue, generation and export waiting. Idle, hidden, unfocused and inactive-workspace time is excluded. This remains an estimate and does not replace the owner study. [Measurement implementation and gaps](PHOTO_STUDIO_MEASUREMENT.md).
- An administrator-only progress report for saved source drafts, with seven-day follow-up, separate complete/pending cohorts and production/internal activity. It follows source replacements, accepted jobs, reused results, successive edits and exact prepared-file identities. An approved-photo use proxy is explicitly distinguished from confirmed receipt. Anonymous abandonment and the full measurement dashboard remain outstanding.
- Responsive dialog scrolling, exact focus restoration through styles and occasions, relative Studio typography, larger secondary controls and crop sliders, and an action bar that moves into the page when enlarged text would make it obscure the workspace. Cancelling unchanged edits no longer leaves a false saving status. [Accessibility review and limits](PHOTO_STUDIO_ACCESSIBILITY_REVIEW_2026-09-17.md).

- Photo Studio no longer statically loads the other workspace interfaces. Deferred tools retain successful loads, show a recoverable loading error, and transfer focus after their saved draft opens. Photo export code is separated from menu/post renderers. The production static-import graph is 19.3% smaller before compression; this is not measured phone latency. [Loading evidence and remaining work](PHOTO_STUDIO_LOADING_REVIEW_2026-09-17.md).

- Crop and light previews reuse one prepared image layer, coalesce pending redraws, cancel superseded source requests and release late bitmaps. Unavailable images have a focus-preserving retry path. Both preview/export rendering match 48 pre-change pixel fixtures under the native test engine. The focused editor keeps the preview beside or above its controls, and gates saving on a successfully painted preview. [Preview evidence](PHOTO_STUDIO_PREVIEW_REVIEW_2026-09-17.md) and [focused-editor review](PHOTO_STUDIO_ADJUSTMENT_REVIEW_2026-09-17.md).

## External inputs and release dependencies

1. Representative, consented restaurant photographs and a live API qualification budget. The requirements specify 180 core outputs, 72 separate holdout outputs, per-style checks, reference matching, repairs and three eight-dish sets. These are planned counts, not completed runs.
2. Real iPhone and Android coverage and independent restaurant participants: discovery round, then 12-owner acceptance round. AI reviewers or browser emulation cannot replace these people/devices.
3. An accountable owner for correction economics, human review, response time and operations alerts.
4. Production publication approval only after the candidate is concrete and the release gates have passed. The existing site is public; this local candidate has not been published.
